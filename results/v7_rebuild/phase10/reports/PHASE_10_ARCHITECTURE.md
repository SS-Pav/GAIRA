# GAIRA V7 — Phase 10 Architecture

The scientific architecture is frozen after Phase 09. Phase 10 wraps it in a runtime platform and
changes no science: cross-surface parity was measured at **max |Δ| = 0.0** and every Phase 09
number reproduces exactly through the runtime path.

---

## 1. The shape

```
                    ┌──────────────────────────────────────────────────────┐
                    │  FROZEN SCIENTIFIC ENGINE — gaira.v7.canonical       │
                    │  preprocess → LSM → CSM → retrieval → chemistry      │
                    │  → confidence → provenance          (Phase 09)       │
                    └──────────────────────┬───────────────────────────────┘
                                           │  the ONLY thing that computes
                    ┌──────────────────────┴───────────────────────────────┐
   adapters ───────▶│  RUNTIME SERVICE — gaira.v7.runtime                  │──────▶ reporting
   (CSV/TSV/TXT)    │  validate · call once · translate · template text    │        (PDF/HTML/JSON)
                    └──────────────────────┬───────────────────────────────┘
             ┌───────────┬─────────────────┼─────────────────┬───────────────┐
        Python SDK      CLI            FastAPI              MCP          Streamlit
```

## 2. The rules

| # | rule | enforcement |
|---|---|---|
| **P-19** | One implementation of every scientific quantity | AST-based static tests over every surface |
| **P-20** | A surface may narrow what it *shows*, never what it *computes* | `include_*` options change the view, not `result_digest` |
| A-09 | Raman-only scientific core | unsupported modality is an **ERROR**, not a warning |
| P-02 | Non-negativity at every layer | asserted in tests |
| P-04 | Provenance is first-class | every result carries the full chain |
| P-13 | No threshold adjustment after seeing results | Phase 05 warning thresholds untouched |

**P-19 is not theoretical.** The first script Phase 10 wrote — the freeze audit itself —
hand-rolled the leave-one-out retrieval loop, dropped every spectrum of the query molecule
instead of only the query spectrum, and reported molecule top-1 of **0.0000**. The phase
reproduced the failure mode it exists to prevent within twenty minutes of starting.

## 4. Atlas identity — two hashes, two meanings

These are different objects and this document, like every other Phase 10 document, uses one name
for each. **Never call both "the atlas fingerprint".**

| term | value | what it identifies |
|---|---|---|
| **Scientific Atlas Fingerprint** | `09ed804a40836f4a05a91ba10900cded` | the scientific atlas identity generated by the Phase 01 build — the corpus, the balanced references and the decomposition that produced them |
| **Frozen Runtime Content Hash** | `2e43ddcca7d3be41c5f9da016fb8277f` | the complete frozen runtime asset identity — the four declared fingerprints together with the reference-molecule set, the chemistry model configuration and the calibrator |

The other three declared fingerprints identify individual frozen artefacts:

| artefact | value |
|---|---|
| LSM registry | `208482d6f7178b5b8f16cace91be55b0` |
| CSM registry | `0b4aa550ccefed3edabdbde5bae11c8d` |
| Phase 05 engine | `20d8bd99ce71f45a125c6a2b1d719e51` |

### How the terms map onto the API fields

The runtime is frozen, so its field names are what they are. The mapping is:

| API / SDK field | carries |
|---|---|
| `engine.fingerprints.atlas` | the **Scientific Atlas Fingerprint** (`09ed…`) |
| `engine.fingerprints.lsm` / `.csm` / `.engine` | the three artefact fingerprints |
| `engine.atlas_fingerprint` · `provenance.atlas_fingerprint` · `/v1/health → detail.atlas_fingerprint` | the **Frozen Runtime Content Hash** (`2e43…`) |

> **Known divergence (documentation vs code).** The field named `atlas_fingerprint` carries the
> Frozen Runtime Content Hash, not the Scientific Atlas Fingerprint. The field name is the
> original source of the ambiguity this patch removes from the prose. Renaming it would be a
> runtime change and is therefore **out of scope for a frozen runtime**; it is recorded here so a
> reader is never misled, and it should be corrected in the first post-freeze interface version.

## 5. Two independent freeze layers

| layer | what it checks | when | failure |
|---|---|---|---|
| Phase 09 declared fingerprints | four values recorded *inside* `PHASE_STATE.json` / `csm_registry_v1.json` | engine load | `FrozenArtifactError` |
| **Phase 10 content digests** | MD5 of all **ten files** the engine opens | before the runtime serves | `FrozenAssetError` |

The second layer exists because the first answers *"did the producing phase claim this artefact?"*
and not *"is the file on disk still the file that phase wrote."* A dictionary could be edited in
place and the declared fingerprint would not move, because it lives in a different file.

## 6. The engine's one Phase 10 change

`GAIRAEngine.prepare()` was extracted from `infer()` — a pure refactor exposing the canonical
processed spectrum read-only, so a client can *display* what the projection consumed instead of
reimplementing preprocessing. The arithmetic is unchanged and the golden fixture digests are
byte-identical before and after.

## 7. Where a future agent connects

The chain is strictly one-directional:

```
        LLM  →  MCP  →  Frozen Runtime  →  Frozen Engine
```

and never

```
        LLM  →  scientific computation
```

An agent calls read-only tools and rephrases numbers the engine computed. It may choose tools,
explain, compare, narrate and summarise. It may **never** compute chemistry, compute a
similarity, estimate a concentration, re-rank retrieval, diagnose disease, or modify inference in
any way. Phase 10 ships no model and requires no cloud account.

## 8. DART — a dynamic perturbation layer, not a modality

**DART is not a new spectral modality.** It is a *dynamic perturbation protocol built on
Raman/SERS measurements*. DART-Met produces

$$ I(\text{wavenumber},\ \text{potential},\ \text{time}) $$

which is **still a vibrational measurement**. Each slice through that volume is a Raman/SERS
spectrum the frozen engine already knows how to read, so nothing upstream needs to change and no
spectral transform needs to be invented.

The correct architecture is therefore:

```
    Dynamic Raman / SERS acquisition        I(wavenumber, potential, time)
                 ↓
    Frozen canonical preprocessing          unchanged
                 ↓
    Frozen LSM projection                   unchanged
                 ↓
    Frozen CSM projection                   unchanged — the canonical representation
                 ↓
    Frozen Chemistry Evidence               unchanged
                 ↓
    Trajectory layer                        NEW: how the representation moves under perturbation
                 ↓
    Dynamic biochemical interpretation
```

DART belongs **downstream** of the frozen representation, as trajectory analysis over a sequence
of ordinary inference results — not upstream as a modality transform. A trajectory of CSM
activations is meaningful only if every activation along it was produced by the same frozen path,
which is precisely the guarantee placing it downstream provides.

> **Known divergence (documentation vs code).** `src/gaira/v7/plugins/modality.py` still registers
> a `DARTAdapter` at the *modality* layer, and its refusal message describes a "mass-spectrometric
> to vibrational correspondence". **That description is wrong** and this section supersedes it.
> The adapter refuses to run, so no incorrect science can result from it, but the string is
> runtime code and a frozen runtime may not be edited. The correct resolution — retire the
> modality-layer `DARTAdapter` and implement DART through `TrajectoryAdapter` — is a post-freeze
> change. Recorded here so the repository is honest about the discrepancy rather than silently
> inconsistent.
